## 📖 O que é este Backlog?

Este repositório é o cérebro vivo do projeto. Aqui não guardamos apenas tarefas — guardamos intenções, hipóteses, melhorias e sonhos que ainda viram código.

O backlog foi desenhado para ser:

## 🔍 Transparente: qualquer pessoa pode entender o que está sendo feito e por quê.
## 🎯 Priorizado: decisões seguem critérios claros, não urgência do momento.
## 🤝 Colaborativo: feito para receber contribuições, feedbacks e correções de rota.

🎯 Priorização & Fluxo
Usamos uma versão leve do MoSCoW + ICE Score para evitar "tudo é urgente":
🔥 Must have → Bloqueia o core. Entra no próximo ciclo.
📈 Should have → Importante, mas pode esperar 1–2 sprints.
💡 Could have → Desejável, entra se houver espaço.
📦 Won't have → Arquivado com carinho. Pode voltar amanhã.

🛠️ Como contribuir
🐛 Encontrou um bug? Abra uma issue com 🐛 bug e siga o template.
💡 Tem uma ideia? Use ✨ feature ou 🧪 experiment. Descreva o porquê, não só o o quê.
🌍 Quer codar? Filtre por 🤝 help wanted ou 🎯 good first issue.
🗣️ Antes de abrir um PR, comente na issue. Evitamos trabalho duplicado.
🔄 Pull Requests devem fechar a issue automaticamente: Fixes #123 ou Closes #456.

⚡ Automação & GitHub Native
Para manter este backlog respirando sem esforço manual:
📁 Crie .github/ISSUE_TEMPLATE/ com os templates acima para preenchimento guiado.
🗂️ Vincule a um GitHub Project (v2) para colunas Kanban que sincronizam automaticamente com labels.
🤖 Use CODEOWNERS para revisão automática em áreas críticas.
🔄 Ative Dependabot e GitHub Actions para CI/CD + limpeza de issues antigas.
🏷️ Configure labeler.yml para rotular automaticamente por caminho de arquivo.
